# 三项研究前提验证：先确认方案值得做，再扩大模型

日期：2026-10-04。依赖基线：`5c77caf8bce8aef2e00ba280a343ad2f7a6f6502`。
这是整体研究方案的补充，不是再次更换最终目标。

## 1. 不变的目标与尚未成立的主张

目标仍是：同一未知窄缝任务内，凭真实交互重新判断下一次起点、进近方向、速度或加速度模式，实际飞到新的出发位置后再尝试，必要时无接触退出或放弃。

当前不能把“小型预测器 + 上下文 + CEM + 安全层”视为已经成立的方法贡献。必须先回答：

1. 不同条件真的需要不同方案吗？
2. 接触前获得、且能完成恢复的传感器经历，是否对判断新方案有用？
3. 这种信息是否改善选择，并有希望抵偿实际交互的代价？

本次工具只做离线诊断。它不训练神经网络，不运行 CEM，不指挥真实无人机。显式上下文条件训练是允许的方法；这里不研究“未经设计而涌现的 ICL”。

## 2. 先冻结实验，不按测试结果制造结论

`configs/research_pilot.json` 给出两个固定探测动作、九个候选方案。九个候选涵盖左右起点、不同速度、不同前后段加速度、进近切线和高度。所有物理条件使用完全相同的一组候选，不能每个条件随便换一组。

这是起始诊断菜单，不是最优动作集合，也不是已验证的真机命令。其 0.04 m 距离阈值继承自离线采集器，可能发生接触；它不是可靠的恢复边界。所有接触和失败都必须保留。要更改菜单或阈值，只能根据开发数据修改并提升配置版本；正式测试条件必须重新留出。

采集时区分两种随机种子：

- `seed` 固定物理任务设置。
- `rollout_seed` 改变试验重复中的随机过程，不重新抽取任务和候选菜单。

默认两次重复只用于运行检查，不构成强统计证据。同一个文件复制两遍不是重复实验。继续使用原采集器的批量布局，暂不声称随机过程对批次大小不敏感。

## 3. 验证一：是否真的需要条件相关的策略选择

将结果组织成“物理条件 × 随机重复 × 共同候选”的表格。

先在训练物理组上选择一个所有条件共用的固定候选。再作一个仅用于诊断的强信息对照：在测试条件的一次重复中找出最优候选，用另一次重复的结果评价它。禁止在同一条随机结果上既挑最优又评估最优。

比较的是**当前固定控制器、执行规则和候选集合下的表现**，不是物理可行性的证明。一次中止不能被标成“继续一定失败”；数值异常不能被标成安全或碰撞。

若不同条件的最优候选名称不同，但跨重复的实际收益为零或不稳定，也不能宣布存在有意义的策略变化需求。

若一个固定方案在强控制器下已经解决全部条件，这是有价值的否定结果。不要调弱控制器、强迫重试，或只保留看起来需要上下文的条件。先判断任务是否还值得引入复杂适应机制。

当前工具只评价仓库现有执行器。尚需把它与校准良好的传统控制器比较，才能回答“不是把低层控制调好就够了吗”。

## 4. 验证二：安全获得的经历有没有增量信息

先采用低成本岭回归，而不是直接训练大型网络。对照包括：

- 无历史预测器：候选参数 + 同一份当前观测。
- 传感器上下文预测器：上述输入 + 已完成恢复的探测经历摘要。
- 错配上下文诊断：在测试集内部按相同探测协议交换历史，保持当前观测不变。

无历史模型同样包含候选与当前观测的交互项，避免把简单的表达能力差异误当成历史价值。两种模型均在训练组拟合、验证组选择正则化参数，测试标签不参与拟合、归一化和模型选择。

### 关键防泄漏规则

**候选尚未执行，不能先看到飞到那个候选起点后才会获得的观测。** 对同一决策，所有候选共用最后一次恢复后已经获得的当前观测。候选自己的 `initial_observation`、执行轨迹和结果只能用于特定预测诊断或监督，不能变成选择该候选之前的信息。

当前工具只使用预先指定的 probe 前缀。所有探测必须完成恢复；一个探测发生接触、终止或未恢复后，后面的独立初始化试验不能伪装成自然延续的历史。报告必须给出被阻断的全部决策及其原因。

历史特征只由模拟机载观测、请求动作及动作后观测计算；不使用真实质量、风、几何净空、查询结果或任务编号。不要把 `target_mask`、未来候选是否安全、测试组真值作为输入。

该简单摘要使用统计量和动作—响应交叉量，完整交互片段的顺序改变可能不影响摘要。因此，“完整片段打乱后性能不变”在这里是预期行为，不是没有学习的证明。错配实验同样不是独立的因果识别定理。

### 解释边界

有收益：支持“这个表示和数据范围内，过去传感器记录提供了当前观测之外的信息”。

无收益：可能是当前观测已经够用、probe 不够信息化、数据不足、模型表示不合适或问题不需要适应。不能单凭一个小模型的失败断言信息在原理上不存在。

本轮仍然预测当前协议下的尝试结果。尚未证明短时运动模型、概率校准或通用世界模型。后续才比较结果代理与短时残差动力学模型的必要性。

## 5. 验证三：预测改善是否真的改善方案选择

预测误差和实际选择收益分别报告，不能互相代替。

默认诊断分数：

`U = 成功(1) / 恢复(0) / 接触或其他有效终止(-1) - 0.01 × 实际仿真秒数`。

这是预先声明的项目内诊断权衡，不是通用奖励、真实安全保证或期刊指标。成功率、接触、时间和失败类型仍需单独报告。可以在开发集预先选择其他合理权重，再冻结评估，不得在测试集调到本方法获胜。

模型在未知测试物理组上，仅凭允许的输入对共同候选打分，再用事先采集、未参与该选择的真实仿真结果评价选中项。无上下文与有上下文对照拥有相同探测预算；否则“多飞了两次”和“更会利用经历”会混在一起。

另报告向上下文方法计入探测时间后，相对不探测的固定方案的条件差值。但目前它仍**不是完整净收益**：

- 未恢复或接触的 probe 前缀未进入预测器条件比较，但全部留在原始统计中。
- 改起点需要实际移动的时间、电量和风险尚未测量。
- 夹具重置代替真实返回，不能被当成免费运动。
- 连续飞行中的观测状态、控制器积分和缓存可能与独立初始化不同。

因此报告的 `net_benefit_status` 固定为 `NOT_ESTABLISHED`。完整系统要在连续任务里计算所有代价，不能把离线条件收益写成“无人机已经越试越好”。

## 6. 数据划分和报告

按物理设置 fingerprint 划分 train/val/test，同一设置的所有候选、probe 和重复留在同一划分。不得按轨迹、帧或文件切分。本次是当前任务生成器内的留出条件，不等于未知机制外推。

置信区间以物理组为单位配对 bootstrap，不把一个任务的九个候选当九个独立任务。小规模结果只能用于诊断；零接触样本也不能推出总体风险为零。

报告内容：共同菜单完整性、原始状态计数、probe 前缀失败、有效组数、跨重复选择收益、各预测目标误差、实际选择收益、接触差异、已记录时间，以及未计入成本。

没有任何一个自动数值门槛会批准真机飞行或宣称满足 Science Robotics。

## 7. 可执行入口

激活本地现有 PyTorch 环境，在仓库根目录运行；不要沿用尚未验证的解释器绝对路径。

```bash
python -m pytest tests/test_research_pilot.py -q

# 使用新的目录名；不覆盖既有数据。真实积分由现有 GapEnv 完成。
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python -m agl.research.collect_pilot \
  --out datasets/research_pilot_01 \
  --tasks 12 --repetitions 2 --batch-tasks 3 --seed 0 --device cpu --trace

OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m agl.research.pilot \
  --input datasets/research_pilot_01/repeat_00.npz datasets/research_pilot_01/repeat_01.npz \
  --out datasets/research_pilot_01/report.json

# 复用已有回放入口。可视化实际安装及显示环境仍需本地验证。
python -m agl.eval.view_eval_rerun \
  --input datasets/research_pilot_01/trace/batch_0000.npz --task 0
```

参数 `--tasks 12` 是小规模管线检查，不是足够发表的试验数量。扩大前先检查耗时、失败分布和数据有效性；16GB 显存不等于训练吞吐或真机实时性的保证。

## 8. 根据结果决定下一步，而不是预设模型必须获胜

| 观察结果 | 下一步 |
|---|---|
| 固定方案已足够好，条件相关选择没有稳定收益 | 检查真实任务约束与控制器；不要为了展示重试而降低控制性能 |
| 不同条件确实需要不同方案，但现有 probe 后无法更好判断 | 检查观测时间、空间覆盖和激励信息；先做真机开放空间测量，不急着加模型参数 |
| 简单传感器模型已经有明显收益 | 把它保留为强基线，再检验小型时序/残差模型是否带来额外价值 |
| 预测改善，但候选选择或接触表现变差 | 检查关键候选排序、分数权重和不确定性；不能按平均误差宣布成功 |
| 条件选择收益不能抵偿 probe 时间 | 改善探测成本或研究何时不必探测，不能强制每次重试 |
| 三个层面都给出可重复支持 | 进入连续闭环：中止、稳定恢复、真实重新定位、更新上下文和重试 |

同时应尽早在既有安全操作范围内获取真实开放空间日志，验证动作接口、时延、载荷与风扰响应。不要等全部模型完成后才第一次对照真机。这里不指定未经平台校准的载荷量、注入延迟或真机近墙速度。

## 9. 进入连续闭环后必须补齐的部分

尝试之间做整体重规划，尝试之中持续检查预测与现实。提交穿越前需验证入口到出口及后方脱离路线；在提交之前保持恢复能力。独立安全权限不是对任意模型失配的免疫。

全系统快照包含环境、控制器积分、参考轨迹进度、缓存观测、模型上下文和规划随机性。更换起点必须通过真实可执行路径完成，并计入任务成本。

这仍然是一条需要证据验证的研究路线，不是“模块做齐即可发表”的承诺。
