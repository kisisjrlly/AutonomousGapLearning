审计日期：2026-10-04。对象：`e5753c7e78826471f5715bf9c6f89051030674f2`，以及导致该提交的方案结论。

## 结论

保留用户目标：“先预测、再尝试，凭真实经历调整下一次起点或运动方式”。但原提交只是第一版仿真结果采集原型，不能视为 Science Robotics 方法已经确立。

主要问题不是网络太小，而是数据会让后续实验回答错误的问题。原方案将仿真真值摘要当作上下文，忽略提前中止的标签适用性，部分参数没有按宣称生效。按原样训练，很可能得到准确拟合代理标签、却不能部署或解释的模型。本轮优先修正这些错误，没有开始训练或部署。

## 1. 研究结论的修正

**1.1 结果代理模型不是自动等于完整世界模型。** 六维候选到几个终局标量，描述的是指定控制器和规则下的结果映射。它可以作为规划工具，但不能据此宣称学到通用物理规律。要扩大主张，需验证对未执行动作的短时响应、状态演化和不确定性。

**1.2 显式训练 ICL 是合法方法。** 将元学习叫“伪 ICL”是此前讨论中不应继承的价值判断。当前路线采用显式上下文条件监督，不能同时声称“只做通用序列预测后自然涌现”。RL²、General-Purpose In-Context Learning by Meta-Learning Transformers 提供了直接先例。

**1.3 架构组合不保证期刊等级。** 结果代理模型、上下文编码、CEM、安全约束均有前驱。必须比较 GP/贝叶斯试验搜索、在线辨识加规划、无上下文预测器、强传统控制。PETS、智能试错、SafeOpt 是相关方法参照，不应只比较旧 PPO。

**1.4 资源推断过度。** 16GB 显存只约束可容纳的模型/批次，不能保证几个月完成或某个机载平台“轻松实时”。先测训练与推理、传感器、通信和保护层的完整耗时，尤其尾延迟。

**1.5 最终范围无需再次膨胀。** 用户要的是同一窄缝任务内换起点/方向/速度曲线。可以围绕这个任务族形成有价值的机器人研究；多平台、跨任务或大规模 Scaling 不是自动录用条件，也不应成为目前的默认开发包袱。

## 2. 代码问题与本轮处置

| 原问题 | 后果 | 本轮处置 |
|---|---|---|
| 历史 AttemptOutcome 含真实净空、真实位置漂移，计划直接作为 context | `audit_*` 不进入模型也不能消除这条真值路径 | 输入改为模拟机载观测/请求动作/下一观测；标签单独监督，query API 不读取历史 target |
| 采集器没保存 IMU/VIO 交互序列 | V0 NPZ 无法验证机载经历学习，也无法事后补造证据 | V1 保存定长采样的真实执行传感器转移、当前观测与掩码；旧数据明确拒绝 |
| `entry_yaw` 只初始化机头，路径始终逐步对准同一中心 | “不同进近方向”与实际代码不一致 | V1 路径切线由该参数决定，参考路径导数回归测试；实际跟踪误差仍须评估 |
| 前段已达到 `entry_speed` 后，正的 `accel_late` 被同一上限截断 | 大量候选在此维度退化成相同参考 | 前段保留速度余量，并测试不同正后段加速度确实改变参考命令 |
| 控制器读取真实质量和最大推力 | 可能提前消除待学习的变化，数据不代表未知动力学下的控制器 | 使用固定名义标定，测试修改隐藏质量/推力不改变同状态控制输出 |
| 同时按质量线性缩放 tmax | 固定 TWR、归一化指令下，质量变化可能不改变轨迹，只改变碰撞能量 | 新任务将电机额定推力与载荷解耦，质量扰动保持电机额定能力，增加运动差异测试 |
| 没有刹停也把 stopping_distance 写成0；未测恢复也写为 false 标签 | 模型会学到伪造的“极短刹停”或错误的恢复分类 | None + target mask；只在无接触前观察到前向速度非正时记录超调；恢复目标只在启动恢复时有效 |
| `terminal_speed` 取 step 之前 | 指标名称与测量时刻错误 | 可选 capture_transition 抓取自动重置前的真实终止状态；测试终止后 reset 不污染 |
| 退回预算是总步数，而非每行进入退回后的独立预算 | 早中止行能多占用时间，方法对比不公平 | 每个阶段独立计数，早中止不“继承”未用完的进近预算 |
| 非有限净空退化为10米 | 数值失败可能被伪造为安全标签 | 异常状态单列，全部目标失效；不填安全常数 |
| 净空注释暗示有限点采样不会漏碰 | 安全性论证不成立 | 删除无依据保证；不改其历史数值定义，明确仍缺连续扫掠验证 |
| 只按本地整数 task_id 分组，没有严格 query 构造 | 跨文件ID重用、目标泄漏及伪历史 | 物理设置 fingerprint 分组；禁止自身、未来、跨任务或未恢复历史；输入与监督结构隔离 |
| 保存路径可能自动加 .npz，且非原子写入 | 重复运行/并发写入可能破坏实验数据 | 强制 .npz、先验证、临时文件+原子无覆盖发布；保留旧文件 |
| 独立并行夹具初始化被口头解释为“多次尝试” | 与真实回撤、重新定位及任务内学习混淆 | 数据显式标记 independent fixture trials；没有宣称已实现连续自主重试 |

### 质量取消的具体原因

原执行器将期望加速度转换为推力时包含 `mass / tmax`。在无饱和的理想部分中，再由动作接口乘 `tmax`、由平移动力学除 `mass`，质量影响被抵消。原场景还用 `tmax = mass * g * TWR`。因此“随机了质量”不等于数据真的包含待适应的载荷效应。

本轮仅修正新数据生成路线，不改变旧 PPO 的任务定义，避免悄悄改变已有基线。

## 4. 本轮以后仍需解决的关键问题

1. 连续任务里的控制器、缓存观测和历史状态共同恢复；`env.snapshot` 单独不足以冻结整个系统。
2. 真实飞到新起点及其成本，而不是采集器夹具初始化。
3. 当前几何固定，控制器仍有状态/几何特权；真实视觉几何估计与不确定性没有实现。未知质量/控制响应的传感器证据，也仍需真机校准验证。
4. 探测数据是有意收集的独立试验；它们可以验证上下文适应，但不是自然涌现或自主实验选择证据。
5. 当前基于距离阈值的中止不是预测式运行时保护。运动中的不确定性、延迟、机体扫掠和穿越后的脱离路线尚需独立验证。
6. 没有训练预测模型；“经历改善未执行方案预测”的核心假设尚无结果，更不能据此承诺 Science Robotics。

## 5. 下一研究里程碑

在少量但有效的固定几何试验数据上：用**相同输入、相同任务划分与预算**比较简单回归/GP、无上下文模型、传感器上下文模型。先评估未执行候选及短时响应的误差/排序/校准，再决定是否接规划器。

科学主张应从“显式训练的传感器上下文适应能否改善尝试策略”开始。获得可信结果后再扩大，不再为了吻合某篇评论文章而反复重写整个研究目标。
