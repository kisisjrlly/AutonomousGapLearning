# 无风窄缝低层姿态基线

日期：2026-10-05。该文档记录当前 `nominal_feedback_hermite_roll_v1` 控制器的边界，不把它写成已经成功穿缝的结果。

## 为什么要先做这一层

0.30 m 开口小于 0.32 m 机体直径。水平机体的横向投影净空为 -0.01 m；静态几何扫描显示约 44° 以上滚转才存在正投影净空。因此，在共同候选、历史上下文和规划器之前，必须先证明候选执行器能主动取得姿态、在进缝时保持姿态并记录接触前后的状态。

## 当前实现

`agl/attempt/executor.py` 的 `ControllerConfig` 现在显式记录：

- 进缝前滚转目标、开始/保持/释放距离；
- 可选的滚转预偏置；
- 姿态误差反馈增益；
- 通过窄缝时的横向加速度前馈和近缝前向滑行策略。

执行器根据完整期望姿态同时控制推力轴、滚转和路径切线，并将控制器版本及配置写入轨迹元数据。姿态控制仍使用仿真真实位姿和已知墙体几何，属于 V0 仿真特权，不能作为机载策略或安全保护层。

## 可复现诊断

```bash
OUT=/tmp/agl-narrow-controller-$(date +%s%N)
python3 -m agl.eval.verify_narrow_gap_controller \
  --out "$OUT" --start-y 0.4 --entry-speed 2.0 \
  --roll-target-deg 65 --device cpu

python3 -m agl.eval.animate_eval_3d \
  --input "$OUT/trajectory.npz" --task 0 \
  --out "$OUT/flight.gif"
```

该入口同时输出 `summary.json` 和实际 GapEnv 轨迹。`success=true` 只表示这一固定执行器、固定任务和预算在仿真中无接触到达成功面；它不表示学习、连续重试或真机安全。

## 当前验收结论

截至本日期，静态姿态几何已通过，但该动态基线仍会在部分候选中接触或在中止后未恢复，尚不能声称无人机已经穿过窄缝。这个失败是低层控制/轨迹问题，不能拿来判定上下文预测无效。因此在动态基线有稳定的成功与失败分布前，暂停新的 pilot、岭回归和 PPO 训练。

下一步应优先：

1. 用实际轨迹定位姿态取得、侧向漂移、穿墙前瞬态三类失败；
2. 将姿态策略（包括滚转符号、预偏置和横向起点）纳入版本化候选，而不是藏在控制器常量中；
3. 在接触检测和恢复门槛都通过后，再重新采集共同候选数据；
4. 最后才比较历史条件预测和同状态重试。
