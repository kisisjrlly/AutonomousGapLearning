# AutonomousGapLearning

自主试探、主动中止并在线适应的端到端无人机窄缝穿越研究。

> 状态：研究起点与项目交接文档，尚未选择仿真器、飞行平台和具体算法实现。
>
> 建立日期：2026-07-15
>
> 默认分支：`main`

## 1. 项目定位

本项目研究一个单一但完整的任务族：无人机面对此前没有见过的窄缝时，利用机载观测自主尝试穿越；如果在执行过程中预测继续飞行将变得不安全，则在发生接触或碰撞之前主动刹停、退出到合适的重试状态，随后利用刚才的经历调整起点、姿态、速度或轨迹，再次尝试。

目标不是实现一个固定窄缝、固定动作脚本，也不是把下列人工模块串成状态机：

```text
窄缝检测器 -> 轨迹规划器 -> 风险阈值 -> 刹车脚本 -> 返回脚本 -> 参数搜索器
```

目标是训练一个具有长期时序记忆的端到端感知运动策略，使观察、接近、试探、减速、主动中止、退出、重新选择尝试方式和再次穿越尽可能成为同一策略从完整交互序列中学到的行为。


## 2. 核心研究问题

本项目的核心问题不是普通的窄缝检测或一次性穿越，而是：

> 一个统一的时序神经网络能否根据自身连续交互历史，自主试探未知物理可行性，并在不接触障碍物的前提下学会何时继续、何时中止、如何退出以及如何修正下一次尝试？

这里的“失败尝试”必须被准确理解为：

- 无人机尚未完成穿越；
- 在线预测表明继续执行的风险已经不可接受；
- 无人机仍处在可以刹停和安全退出的状态；
- 策略主动中止本次尝试并返回重试区域；
- 障碍物接触和碰撞不是正常的数据收集机制。

因此，本项目关注的是 `learning from safely aborted attempts`，而不是 `learning by crashing`。

## 3. 预期行为

一次理想的完整交互可以表现为：

```text
悬停观察
  -> 主动改变视角
  -> 选择进近起点、速度和侧身姿态
  -> 渐进进入窄缝
  -> 根据新观测持续修正对净空和自身状态的判断
  -> 发现当前尝试的风险持续升高
  -> 在 point of no return 之前刹停
  -> 退出并返回可重试状态
  -> 利用刚才的经历改变下一次动作
  -> 再次尝试
  -> 穿越成功，或经过有限次尝试后判断当前条件下不可通行
```

重要概念是 `progressive commitment`，即渐进式承诺。无人机不能在最初观测不充分时一次性承诺整条高速穿越轨迹。它每前进一步，都必须继续评估：

1. 当前穿越仍然具有足够的成功可能性；
2. 当前状态仍然保留一条可执行的刹停或退出轨迹。

## 4. “端到端”的准确含义

部署时，核心策略可以抽象为：

```math
(a_t, h_{t+1}) = \pi_\theta(o_t, a_{t-1}, h_t)
```

其中：

- `o_t`：RGB或其他机载视觉、IMU、电机状态、可选高度和里程计信息；
- `a_{t-1}`：上一时刻执行的动作；
- `h_t`：RNN、状态空间模型或Transformer保存的交互历史；
- `a_t`：期望推力与机体角速度，或短时间动作序列；
- `theta`：策略参数。

核心决策链在部署时不应依赖人工编写的任务状态机。网络应从传感器历史直接生成具有时间连续性的飞行动作，并使“观察、试探、中止、退出、调整和重试”作为行为模式自然出现。

**能力是目标，方法是手段。** 本项目的最终交付物是一个能力：无人机面对未知窄缝时，能在接触前安全中止、掉头返回、调整后再尝试。获取该能力的途径是可替换的手段，不是目标本身，包括但不限于：

- **端到端强化学习**（当前实现）：单一循环策略直接从观测生成动作，试探/中止/重试作为行为涌现；
- **模仿学习 / 离线强化学习**：从专家轨迹（含主动中止轨迹）或离线数据集学习；
- **带学习组件的规划与控制**：学习风险/可行性模型，接入轨迹规划与安全过滤；
- **大语言模型 / 视觉-语言模型的思维链显式推理（LLM chain-of-thought）**：以
  command-measurement-action 方式，由 LLM 维护任务证据状态、显式推理"可穿越性命题是否已验证"
  （避免假确定性），决定继续/中止/调整策略，底层由传统控制器或学习到的低层策略执行动作
  （决策层低频、控制层高频的分层结构；详见 docs/tech-selection.md §11 与
  paper/evidence-validity-framing.md）。

因此论文的贡献第一序是“能力 + 可复现的获取路径 + 与获取方法无关的评估协议”，而非某一种特定算法。

端到端不等于以下错误要求：

- 不要求从RGB直接控制每个电机才算端到端；输出推力和机体角速度、由成熟飞控执行内环，是更合理的现实边界；
- 不要求物理、渲染和相机链路全部可微；策略梯度、模仿学习、离线强化学习和潜空间世界模型都可以处理不可微环境；
- 不要求系统没有任何安全保护；最小安全内核可以独立否决明确不可恢复的动作，但不能替代策略完成窄缝识别、尝试选择或恢复规划；
- 不等于没有训练目标。没有目标、奖励、偏好或行为先验时，“自主选择”没有可判断的正确性。

## 5. 在线适应方案A：权重固定，行为改变

方案A在真实飞行期间固定网络权重，通过时序记忆改变后续行为：

```math
h_{t+1}=f_\theta(h_t,o_t,a_t), \qquad a_{t+1}=g_\theta(h_{t+1})
```

第一次尝试的观测、动作、刹停位置、实际姿态误差和退出过程进入上下文记忆。第二次尝试时，网络虽然没有进行反向传播，但可以因为历史不同而选择新的起点、姿态和速度。

这种能力需要通过元训练获得。训练样本不能只是一次独立穿越，而应是包含多次尝试的完整长序列，并且在尝试之间保留模型记忆：

```text
任务实例开始
  -> 尝试1并主动退出
  -> 尝试2并再次调整
  -> 尝试3成功或判定不可行
任务实例结束后才重置长期上下文
```

训练任务应随机变化窄缝宽度、厚度、朝向、形状、光照、纹理、风扰、质量、惯量、控制延迟、相机参数和状态估计误差，使模型学习“如何利用尝试历史推断当前任务”，而不是记忆一个固定动作。

相关技术范式包括：

- recurrent reinforcement learning；
- meta reinforcement learning；
- in-context reinforcement learning；
- history-conditioned policy；
- action-chunking sensorimotor Transformer。

优点：

- 适应立即发生，不需要飞行中反向传播；
- 计算量和显存要求相对可控；
- 不会因一条错误经验直接破坏基础策略；
- 权重固定，便于回放、复现和安全验证；
- 适合作为真实无人机上的第一版系统。

局限：

- 适应能力受元训练任务分布限制；
- 清除上下文后，短期经验通常不会永久保留；
- 对完全分布外问题可能只表现为保守退避，而不能形成新技能；
- 论文中应准确称为“在线适应”或“上下文学习”，不能直接等同于持续更新参数的终身学习。

## 6. 在线学习方案B：真正更新网络权重

方案B在第 `k` 次或一批尝试结束后，利用新经验更新参数：

```math
\theta_{k+1}=\theta_k-\alpha\nabla_\theta\mathcal{L}(D_k)
```

`D_k` 可以包含图像、IMU、动作、预测轨迹、最小净空、主动中止位置、退出代价和最终是否成功等数据。更新后的知识可以跨任务、跨上下文甚至跨重启保留。

可能更新的学习目标包括：

- 未来视觉或潜状态预测；
- 动作后的状态变化和控制误差预测；
- 最小净空和安全退出可行性预测；
- 穿越成功概率及其不确定性校准；
- 策略价值或动作分布；
- 当前机体质量、惯量、延迟和风扰对应的适配参数。

优点：

- 新经验可以长期固化；
- 可以逐渐适应特定无人机的结构偏差、磨损和载荷；
- 理论上有机会超过原始元训练分布；
- 更符合“持续在线学习”的严格定义。

主要风险：

- 主动退出只表示模型认为风险高，不等于继续飞行一定会碰撞；将退出直接当作失败标签会产生自证循环并使策略越来越保守；
- 一次感知错误或错误自标注可能污染策略；
- 会发生灾难性遗忘和策略漂移；
- 更新后的策略不再自动继承更新前的安全验证结果；
- 真实窄缝成功信号稀疏，直接在线策略梯度样本效率低且风险高；
- 更新视觉与控制主干的计算、存储和验证成本较高。

因此，禁止把“从随机初始化开始，在真实无人机上不断碰撞并在线强化学习”作为本项目的基本路线。

## 7. 当前技术判断：快慢双层学习

项目当前的首选路线是：

> 先用方案A建立可靠的上下文在线适应，再在稳定基础上加入受约束的方案B；最终形成短期快速适应与长期缓慢固化并存的系统。

建议结构：

```text
快速层：
冻结基础策略参数
使用RNN/Transformer上下文记忆
在同一个窄缝任务的多次尝试中立即改变行为

慢速层：
保存经过筛选的真实交互数据
只更新小型Adapter、LoRA或明确隔离的适配参数
在历史安全数据和仿真回放中验证
验证失败则回滚，不修改基础策略
```

不建议初期执行以下操作：

- 每个控制周期在线更新权重；
- 在飞行中更新完整视觉和控制主干；
- 仅根据成功/失败二值信号直接更新策略；
- 让未验证的新权重立即获得完整控制权限；
- 把所有主动中止样本自动标记为“继续一定会碰撞”。

## 8. 初步系统边界

### 8.1 输入

第一版建议输入：

- 前视RGB视频；
- IMU；
- 上一时刻推力和角速度指令；
- 电机或飞控状态；
- 可选的视觉惯性里程计和高度信息。

不应在研究开始时同时引入多种深度相机、激光雷达和复杂主动相机参数。是否增加深度输入应由RGB基线和安全需求的实验结果决定。

### 8.2 输出

第一版建议输出短时间动作块：

- 总推力；
- roll、pitch、yaw角速度或期望姿态；
- 未来若干控制步的动作序列。

成熟飞控负责高频姿态内环。直接输出四个电机转速可以作为后续研究，不应成为初始系统的必要条件。

### 8.3 网络

初步候选是视觉编码器加长上下文时序模型：

```text
RGB序列 + IMU + 本体状态 + 历史动作
                    |
                    v
             视觉/状态Token
                    |
                    v
      Sensorimotor Transformer或RNN
                    |
                    v
            未来动作序列Action Chunk
```

训练时可以使用未来观测、状态变化、净空和不确定性预测等辅助目标，帮助模型形成内部世界状态。部署时仍由统一策略直接产生动作，辅助训练头不应演变成人工任务状态机。

## 9. 安全原则

“不能撞墙”是系统设计目标，但任何纯学习策略都不能仅靠口头设定保证零碰撞。真实实验必须区分：

- 正常主动中止：无接触，属于预期行为；
- 轻微软性保护接触：只能作为早期受控实验的兜底事件；
- 高能碰撞：不可接受事件。

建议保留一个最小、任务无关的安全内核。它只判断候选动作是否会使无人机失去刹停或退出能力，并拥有否决权；它不负责选择窄缝、规划正常路径、判断如何重试或生成任务行为。

安全内核至少应考虑：

- 当前速度和姿态下的三维刹停距离；
- 推力、角速度、延迟和电池状态约束；
- 完整机体及桨叶保护结构的扫掠体积；
- 状态估计和几何感知的不确定性；
- 是否仍存在返回安全集合的可行轨迹。

真实实验早期还应使用软质窄缝边界、安全网、桨叶保护罩、低速限制和独立急停。外部动作捕捉可以用于评估和安全兜底，但不能作为核心策略在部署时必需的特权观测。

## 10. 任务分布，而不是固定场景

“只实现一个场景”在本项目中表示只研究窄缝穿越任务族，不表示只使用一个固定窄缝。至少应变化：

- 宽度、高度、厚度和朝向；
- 矩形、倾斜或有限非规则边缘；
- 进近空间和退出空间；
- 光照、纹理和背景；
- 横向风和局部扰动；
- 无人机质量、惯量和控制延迟；
- 相机标定、模糊和状态估计误差。

训练集、验证集和真实测试集必须按照窄缝实例或参数范围划分，防止把固定动作记忆误判为在线适应。

## 11. 训练信号

端到端不等于只使用一个稀疏成功奖励。初期可以采用约束优先的多目标训练：

1. 首先约束高能碰撞和不可恢复状态；
2. 在安全约束内提高穿越成功率；
3. 减少不必要的尝试次数、时间和能耗；
4. 鼓励能够降低关键不确定性的观察和试探；
5. 奖励主动中止后的稳定退出，但避免通过反复退出刷取奖励。

训练数据可来自：

- 仿真中的专家轨迹和失败前主动中止轨迹；
- 规则控制器、优化器或人类遥控产生的示范；
- 仿真强化学习产生的多次尝试序列；
- 真实无人机的低速、安全边界内交互；
- 后期由稳定策略自主收集并经过筛选的数据；
- **基于大语言模型思维链的系统**（见 §4 候选途径清单）：由 LLM 生成"测量查询→接受/拒绝命题→
  调整策略"的决策轨迹，可作为高层次决策示范或先验，供模仿/离线学习蒸馏，也可直接作为
  分层控制的高层决策器（底层由传统控制器执行）。

仿真器是否采用Isaac Sim、MuJoCo、Genesis或其他方案，应在下一阶段根据视觉真实性、并行效率、无人机动力学接口和传感器延迟建模能力进行选择，README当前不预设答案。

## 12. 评估指标

不能只报告最终成功率。至少需要记录：

- 首次尝试成功率；
- 限定次数内最终成功率；
- 从第1次到第2次、第3次尝试的条件成功率变化；
- 每个任务达到成功所需尝试次数；
- 主动中止率和中止时剩余净空；
- 中止后成功返回重试状态的比例；
- 障碍物接触率、高能碰撞率和人工干预率；
- 最小净空、最大姿态误差和最大控制饱和时间；
- 对未见窄缝、未见风扰和未见机体参数的泛化；
- 清空上下文后性能变化，用于证明方案A确实使用历史；
- 冻结模型与在线Adapter更新模型的比较；
- 参数更新前后的旧任务保持率，用于评估遗忘；
- 实际机载计算延迟、频率、功耗和显存占用。

关键消融实验包括：

- 无历史记忆；
- 每次尝试后清空记忆；
- 只有当前帧；
- 不允许主动改变观察视角；
- 不提供过去动作；
- 不进行元训练；
- 完整权重更新、仅Adapter更新和完全冻结；
- 无最小安全内核；
- 人工规则重试基线与统一策略。

## 13. 分阶段路线

### 阶段0：问题和平台冻结

- 明确机体尺寸、推重比、机载计算平台和传感器；
- 定义窄缝参数范围、成功条件、主动中止条件和不可接受事件；
- 选择仿真器与低层飞控接口；
- 建立统一日志、回放和指标格式。

### 阶段1：单次穿越基线

- 建立从视觉和本体状态到推力/角速度的端到端时序策略；
- 完成随机窄缝上的单次穿越；
- 建立动作延迟、风扰、机体参数和视觉域随机化；
- 不在这一阶段宣称在线适应。

### 阶段2：主动中止和自主退出

- 将完整尝试过程纳入训练；
- 学会在风险升高时减速、刹停和退出；
- 验证策略不会把“退出”学成逃避所有任务的捷径；
- 建立最小安全内核及其独立测试。

### 阶段3：上下文在线适应

- 一个训练episode包含多次连续尝试；
- 尝试之间保留模型记忆；
- 证明第二次和第三次尝试利用了此前信息；
- 与无记忆策略、手工参数搜索和传统重规划比较。

### 阶段4：仿真到现实

- 先在软质边界、低速和外部安全系统下测试；
- 逐渐减少外部特权信息；
- 评估真实感知误差、延迟和刹停模型偏差；
- 形成完全机载的上下文适应基线。

### 阶段5：受约束的长期参数学习

- 仅更新Adapter或LoRA；
- 使用经验筛选、旧数据回放、保守更新和自动回滚；
- 先离线影子验证，再允许新参数控制真实无人机；
- 证明长期固化带来收益且不会破坏旧任务和安全能力。

## 14. 当前结论

截至项目建立时，已经达成以下判断：

1. 研究范围先限制为未知窄缝的自主尝试、主动中止、退出、调整和重试。
2. “失败”主要指无碰撞的主动中止，不以撞墙作为正常学习方式。
3. 核心策略应是统一的长时序端到端神经网络，而不是人工任务状态机。
4. 端到端策略不要求仿真和渲染全流程可微。
5. 第一版优先采用冻结权重的上下文在线适应，因为它更稳定、易验证且适合真实飞行。
6. 真正的参数更新放在第二阶段，只更新隔离的小型适配参数，并要求验证和回滚。
7. 最终目标是快慢双层学习：短期经历进入上下文，可靠经验再缓慢固化到参数。
8. 真实系统保留最小安全否决层，但该安全层不承担任务策略和重试逻辑。
9. 一个固定窄缝不能验证学习能力，必须使用一个有明确训练/测试划分的窄缝任务分布。
10. 当前项目从零建立研究设计，不默认复用任何旧项目代码。

## 15. 仍需研究的问题

- 使用纯RGB、双目、深度还是RGB加事件相机；
- 长时序模型采用RNN、Transformer、状态空间模型还是潜空间世界模型；
- 动作输出频率、动作块长度及低层飞控边界；
- 如何生成足够丰富且不是人工状态机复制品的专家序列；
- 如何从主动中止数据中学习，而不形成“越退出越保守”的自证偏差；
- 如何估计“继续飞行的反事实结果”，同时不真的发生碰撞；
- 如何把安全约束纳入训练，又避免安全层替代策略学习；
- 如何证明后续尝试确实利用了前次经历，而不是随机波动；
- 如何在有限真实样本和单卡显存条件下训练视觉时序策略；
- 如何界定任务不可行，并让策略在有限尝试后合理放弃。

## 16. 给后续Codex线程的工作约束

新的Codex线程开始工作时，应先完整阅读本README，并遵守以下约束：

- 不要把讨论自动拉回 `DiffPhysDrone`、可微渲染、曝光控制或世界模型替代仿真等旧路线；
- 不要未经论证就复制旧项目文件；
- 不要把系统重新拆成手工编写的任务状态机；
- 不要声称纯神经网络能够数学保证绝对零碰撞；
- 不要把主动中止样本直接等同于真实碰撞标签；
- 不要一开始就在真实无人机上更新完整网络；
- 每项实现都应说明它服务于哪一个研究假设和评估指标；
- 优先建立最小、可验证的纵向闭环，再扩大模型、数据和平台复杂度。

建议新线程的第一项任务是：在不编写训练代码之前，完成技术选型文档，确定无人机平台、仿真器、传感器、动作空间、时序模型、训练算法、安全边界、数据格式和阶段1的验收指标。

## 17. 一句话项目主张

> 最终能力：无人机面对未知窄缝时，能利用机载观测自主试探，在接触前安全中止并掉头返回，
> 根据失败经历调整起点、姿态与策略后再次尝试，直至穿越或判定不可通行。
>
> 该能力是目标；获取手段（端到端强化学习、模仿学习、离线强化学习、规划+学习组件等）是可替换的途径。
> 本项目当前以"从安全中止的真实尝试中进行上下文学习"作为主验证路径（方案A），
> 并以评估协议与消融矩阵验证的是"能力是否获得、获取路径是否可复现"，而非绑定某一种算法。
